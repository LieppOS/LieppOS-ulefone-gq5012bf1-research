# Critical Phase 5 inference

Treat this as a hypothesis to prove, not as final truth:

```text
The immediate B -> unbootable -> A fallback is more consistent with
bootloader/AVB rejection than with an ordinary runtime crash that merely
consumes one retry.
```

Reason:

The pinned AOSP/Lineage `external/avb` reference A/B flow should be inspected directly.

In the reference flow:

```text
verification rejection can mark a slot unbootable

an ordinary selected-but-not-yet-successful bootable slot normally
has tries_remaining decremented
```

An unlocked device is normally expected to allow certain verification errors:

```text
public-key rejected
verification error
rollback-index error
```

But errors such as these are different:

```text
invalid metadata
unsupported libavb version
I/O error
invalid arguments
```

and may still prevent selection/boot.

The OEM MediaTek bootloader may not exactly implement the reference flow.

Therefore Phase 5 must prove actual armol behavior.
