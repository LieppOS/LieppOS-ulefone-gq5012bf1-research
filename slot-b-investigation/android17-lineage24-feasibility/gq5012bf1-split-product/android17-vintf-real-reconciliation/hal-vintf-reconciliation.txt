#                   ODM dsds content is a strict subset/duplicate of vendor manifest entries)
#                 + vendor APEX com.google.android.widevine (stock vendor/apex, VENDOR partition apex)

#     compatibility_matrix.8.xml (addAll), 202404/202504/202604 (addAllAsOptional),
#     compatibility_matrix.device.xml + compatibility_matrix.lineage.xml (level unspecified => treated as 8).
#     compatibility_matrix.7.xml only feeds checkDeprecation (level < device level).
#
# libvintf android-17.0.0_r1 fatality rules (from source, not opinion):
#   * HalManifest::checkCompatibility(device manifest, FCM) checks ONLY sepolicy version (+kernel on host).
#     FCM <hal> entries are NOT required: libvintf 17 does not even parse optional=; a HAL that is in the FCM but
#     absent from vendor is NEVER a checkvintf failure  => MISSING FROM VENDOR / FRAMEWORK-ONLY are informational.
#   * VintfObject::checkUnusedHals (target-level>=R): every vendor instance must match some FCM instance
#     (format, package, version-in-range, interface, instance/regex) => EXTRA VENDOR HAL / VERSION MISMATCH /
#     INSTANCE MISMATCH on the VENDOR side are FATAL.
#   * VintfObject::checkDeprecation: vendor HAL version older than allowed by the level-8 matrix => FATAL.
#   * Framework manifest vs vendor device matrix: ONLY <vendor-ndk> and <system-sdk> are checked; framework HALs
#     required by the vendor DCM are NOT checked by libvintf (runtime-only concern).
#   * Transport (<transport>) is never compared against matrices by libvintf.
