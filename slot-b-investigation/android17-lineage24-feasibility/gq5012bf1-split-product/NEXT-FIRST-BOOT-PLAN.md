# Next first-boot plan

## Safety gate remains closed

```text
SHARED_USERDATA_DIRECT_TEST_SAFE=0
```

Android 17 can advance Settings, telephony/SMS, and MediaProvider state beyond
Android 16. Nothing in this build changes the prior downgrade conclusion.
Current userdata and metadata must not be mounted by this candidate.

## Recommended next action

1. Validate DSU support end-to-end on this model without installing the new
   image and prove that DSU uses separate guest userdata.
2. Use the split system/product/system_ext contents as the device-product
   reference, but create an appropriate DSU artifact if the loader requires a
   folded system image. Never point DSU at current shared userdata.
3. Capture first Android 17 init, linker, VINTF, SELinux, zygote, SystemServer,
   radio, graphics, camera, KeyMint, and vold logs.
4. Convert only observed failures into reviewed device-tree/property/sepolicy
   changes; do not mass-generate allows.

## Before any eventual Slot-B write

- replace host AOSP test keys with the accepted B-chain key strategy;
- use rollback location 2 for the real `vbmeta_system` chain, matching current
  B, and preserve locations 3/4 for boot/vendor chains;
- reconcile the known current `init_boot` descriptor mismatch;
- generate root `vbmeta_b` descriptors for product/system_ext and a child
  `vbmeta_system_b` descriptor for system, all flags 0;
- verify the complete chain against unchanged boot/vendor/DLKM images;
- define isolated first-boot data architecture—shared userdata is not allowed;
- obtain separate explicit authorization before any write or slot activation.

No flash package is generated by this task.
