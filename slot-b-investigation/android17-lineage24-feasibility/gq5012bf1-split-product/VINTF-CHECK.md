# Host VINTF compatibility check

## Inputs

Framework side came from the final Android 17 split product:

```text
/system      .../target/product/gq5012bf1/system
/system_ext  .../target/product/gq5012bf1/system_ext
/product     .../target/product/gq5012bf1/product
/apex        .../target/product/gq5012bf1/apex
```

Device side used the untouched stock V15 extraction:

```text
/vendor /mnt/SamsungSSD/TIER3/phase1/extracted/mounts/run-20260718T120318Z/vendor
/odm    <vendor>/odm
ro.product.first_api_level=35
ro.vendor.api_level=34
ro.boot.product.hardware.sku=dsds
ro.boot.product.vendor.sku=dsds
```

The DSDS selection matches the captured dual-SIM product. No matrix was edited
inside either extracted vendor or built framework output.

## Iteration 1: expected device-tree failure

`checkvintf --check-compat` returned `INCOMPATIBLE`: 90 instances present in
the stock vendor+DSDS manifests were not declared by the generic framework
matrices. These were nonstandard radio instance names plus MediaTek, Mali, and
Ulefone/YFT HALs. Every line is preserved in
`VINTF-INCOMPATIBILITIES.tsv` and classified `DEVICE_TREE_FIX`.

## Fix

`assemble_vintf -m --hals-only` generated a reference skeleton from the exact
stock manifest and installed fragments. That skeleton was reduced to only the
90 reported misses, coalesced into 47 HAL/interface groups, and installed as:

```text
DEVICE_FRAMEWORK_COMPATIBILITY_MATRIX_FILE += \
    device/ulefone/gq5012bf1/vintf/framework_compatibility_matrix.xml
```

Every entry is required; none uses `optional="true"`. This records the real
device contract rather than weakening FCM 8.

## Iteration 3 re-check (final property source)

The final iteration removed the hand-written `ro.product.first_api_level=35`
override from `device.mk`; the level is now declared only as
`PRODUCT_SHIPPING_API_LEVEL := 35` and generated by the build system. The host
check was re-run with byte-identical inputs (same built framework directories,
same stock vendor + DSDS ODM side, same four properties) and again returned
`COMPATIBLE`. The audit is preserved in
`/mnt/WDBlue/TIER3-phase5-android17/split-iterations/i3-generated-properties/verify.log`.

## Final result

The rebuilt image exposes `system/etc/vintf/compatibility_matrix.device.xml`.
The same host command then returned:

```text
getDeviceHalManifest: Successfully processed VINTF information
getFrameworkHalManifest: Successfully processed VINTF information
getFrameworkCompatibilityMatrix: Successfully processed VINTF information
getDeviceCompatibilityMatrix: Successfully processed VINTF information
COMPATIBLE
```

The host invocation omitted `--kernel`, so the result is accurately:

```text
COMPATIBLE (HAL/matrix check; kernel requirements skipped)
```

Kernel 6.1/GKI compatibility is documented separately in the parent feasibility
research; no matrix was weakened to hide a kernel failure.
