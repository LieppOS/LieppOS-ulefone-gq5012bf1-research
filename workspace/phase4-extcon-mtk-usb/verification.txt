1b. THE CONFIG_TCPC_CLASS GATE (root cause of the silent TCPC gap)
----------------------------------------------------------------
The Type-C half of the driver is compiled out unless the preprocessor macro
CONFIG_TCPC_CLASS is defined. The private gate name originally used in this
reconstruction (CONFIG_MTK_TCPC_CLASS) built clean and *did* emit the procfs
skeleton, yet produced a module with **zero** tcpc_class references:

  inc/tcpm.h selects between the real externs and no-op stubs on exactly that
  spelling --
      #if IS_ENABLED(CONFIG_TCPC_CLASS)
              extern struct tcpc_device *tcpc_dev_get_by_name(const char *name);
              extern int register_tcp_dev_notifier(...);
              extern int tcpm_inquire_remote_cc(...);
      #endif
      #define TCPC_CLASS_NA
      static inline int register_tcp_dev_notifier(...) { return 0; }   etc.
  so a differently-named gate silently bound every call to a `return 0` stub and
  linked successfully. Any -D gate must therefore reuse the vendor macro name.
  Fixed: Makefile passes -DCONFIG_TCPC_CLASS=1 (both ccflags-y for M= builds and
  ccflags-$(CONFIG_EXTCON_MTK_USB_RECON_TCPM) for Kconfig builds); the source
  uses IS_ENABLED(CONFIG_TCPC_CLASS). tcpc_class baseline was built with
  -DCONFIG_TCPC_CLASS_MODULE=1; the consumer only passes opaque struct pointers,
  so it does not need that second define.

---------------------------------------------------------------------

                external-ish linkage in stock, merged into .rodata locally here.
only in recon : mtk_usb_extcon_set_vbus (0x348), mtk_usb_extcon_procfs_init,
                yft_tiny2c_mode_work.
Explanation: stock has NO out-of-line mtk_usb_extcon_set_vbus -- clang inlined it
into its three callers. The arithmetic closes: notifier 0x832 (2098 B) versus
1142 B here is exactly the ~348 B set_vbus body plus its two call sites, and
probe (2252 vs 2028) / detect_cable (468 vs 532, +call overhead) move in the
opposite directions. So these are inlining-shape deltas, not behaviour deltas.
get_otg_select_gpio, usb_cc_smt_procfs_open, mtk_usb_idpin_handle,
mtk_usb_extcon_set_role/update_role/psy_notifier differ by <= 16 B (padding /
pointer-auth scheduling).
