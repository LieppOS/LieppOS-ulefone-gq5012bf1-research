## Dependency boundaries

- PMIC drivers use GKI dev_get_regmap/regmap/regulator APIs; empty depends= does not prove
  independence from parent MFD/SPMI devices. mtk-spmi-pmic remainsG, PMIF remainsD.
- RT6160 uses GKI I2C/regmap/GPIO APIs but needs an actual responding client and optional
  GPIO provider. Device-controller prerequisites are not symbol-level module imports.
- Prior PINCTRL/BOOT-CLOCK/STORAGE certifications are reused as relevant accepted witnesses,
  never reclassified/rebuilt. Their success does not certify PMIC or DVFSRC providers.
- Source A status here is the consumer's full implementation + independently reproducible
  correct ABI inputs. Dependency source gaps remain explicit integration/runtime blockers.

Full-file SHA-bound verification rejects any unexplained behavior byte. Exactly20 GNU
build-ID descriptor bytes are eligible for normalization; actual raw differing offsets,
stock/rebuild IDs and permitted range are in acceptance.json. No signature or ABI masking.
