# MT6637 role and revision evidence

## Conclusion

The GQ5012BF1 connectivity radio is the **MT6878 integrated CONNSYS (connv2, "SOC7_0",
CONNAC2X) D-die** plus an **MT6637 A-die** RF companion carrying Wi-Fi (2x2), Bluetooth, GNSS and
the FM receiver. There is **no separate combo chip** on SDIO/PCIe/UART, no MT6686 GNSS A-die and
no external FEM.

Strictly, "MT6637-WIFI" names the RF die. The Wi-Fi MAC/baseband (WF WM MCU, WFDMA) and the BT
BGF MCU live in the MT6878 CONNSYS. The kernel driver binds to the SoC (`mt66xx_chip_info_soc7_0`,
`CONNAC20_CHIPID=6878`).

## Inferred strap state (STRONGLY_SUPPORTED)

The ConnFem HWID (`connfem/epa-elna-mtk/hwid/gpio = <&pio 131 0>, <&pio 132 0>, <&pio 92 0>`,
LSB-first per `connfem_dt_parser.c` `hwid |= (gpio_value & 1) << i`) must hit a `nofem/nofem`
entry: index 0, 1 or 2 (prior CONNFEM result). The consys strap uses the **same three GPIOs in
reverse order**, and the live SKU is 6637 (`adie-sku` code 0):

| ConnFem idx | GPIO131,132,92 | consys idx (LSB-first, order 92,132,131) | adie-sku code | SKU |
|---:|---|---:|---:|---|
| 0 | 0,0,0 | 0 | 1 | 6631 ✗ |
| 1 | 1,0,0 | 4 | 2 | 6631+6686 ✗ |
| **2** | **0,1,0** | **2** | **0** | **6637 ✓** |

The answer is the same if LK reads the GPIO list MSB-first, because GPIO132 is the middle bit in
both lists. So **GPIO132 = 1, GPIO131 = 0, GPIO92 = 0**. That makes the ConnFem HWID 2
(nofem/nofem) and the A-die SKU 6637. The remaining assumption is the SKU code meaning
(`mt6637 = 0`), which comes from the MTK reference DT comment and LK strings, not LK source. A
read-only runtime check is in `../runtime-test-plan.md`.

## Mismatch worth knowing

The static DTB and the `vendor/firmware/BT_FW.cfg` key (`bt_antswap[6878][6631]`) say **6631**.
The silicon, the live DT, the loaded firmware and the kernel ops table say **6637**. Rebuilding a
DTB without LK patching would bind the 6631 ops table: a different thermal formula, a different
PMIC ops table, and no pre-cal backup. The BT antswap entry is ignored at runtime (`ptr is NULL,
do not get corresponding tag. Ignore antswap setting`), because the 6878/6637 key does not exist.
