## Conclusions for this axis

1. **No module-level gap.** Every one of the 457 shipped kernel modules resolves to
   either a component owner (238) or a documented generic/dead class (219);
   `coverage=E` is empty. The kernel-module axis of the index is therefore complete.
2. **Generic mass is real, not laziness.** 205 modules are class C and every one of
   them is justified by an existing source-provenance record in
   `OEM-KERNEL-MODULES/evidence/module-map.csv` (167 `LIKELY_PLATFORM_MATCH`,
   38 `DIRECT_SOURCE_MATCH`). 48 of them are perf/thermal/clock/DVFS/SWPM/LPM
   vendor glue, 11 are the `met_*` MEU tracer family: for a same-BSP custom kernel
   these travel as vendor platform code, they need no board-specific RE.
3. **The GPU kernel driver has no owner of its own.** `mali_kbase_mt6878_r44.ko` is
   currently B via a prose mention inside `TMEM-FFA`; nothing documents the Mali
   Bifrost DIF/KMD side. Decision needed: either a dedicated `GPU-KERNEL` component
   or an explicit class C record stating "binary DDK + KMD carried as-is".
   Same question for `mali_mgm`/`mali_dmabuf_test`/`mali_prot_alloc` and
   `mtk_vcodec-{dec,enc}-v1`/`mtk-vcu` (media VPU) today C via `VENDOR-BLOB-HAL-INVENTORY`.
4. **The MTK charging framework is spread over six packs with no single inventory**:
   `adapter_class`/`charger_class`/`mtk_charger_algorithm_class` -> `TCPC-CLASS`,
   `mtk_pep40` -> `MT6375-CHARGER`, `mtk_pep`/`mtk_pep50` -> `SH366003-FUEL-GAUGE`,
   `mtk_pd_adapter`/`mtk_pd_charging` -> `PD-PPS-UFCS`, `mtk_charger_framework` ->
   `MT6375-CHARGER`, `sc8571_charger` -> `BATTERY-PACK`. Coverage exists, but no one
   component can currently answer "what does the charging stack look like end to
   end". Merge candidate or a cross-pack index row is the follow-up.
5. **`mtk-composite.ko` (USB composite gadget) had no owner** in any pack inventory:
   curated to `MTU3-SSUSB` (B) because that scope already declares "gadget-side
   vendor modules"; the pack still has no inventory row for it.
6. **Dead payload** is 14 modules (D): 11 `met*`/`scheduler_ext` debug-eng baggage,
   `nfc.ko` (the ST21NFC stack uses a misc char device, not the in-kernel NFC core),
   and `snd-soc-tfa98xx.ko` (NXP amp driver shipped although the board fits AW88394).
