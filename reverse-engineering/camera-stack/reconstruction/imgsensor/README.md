## How each part was reconstructed

### Framework (adaptor-*, frame-sync, virt-sensor) — 524 functions, 523 exact
Baseline NothingOSS MT6878 + the proven 14-slot custom-LDO `adaptor_ctx` change gave
507 identical. The remaining **25 ODM-modified** and the framework part of the **36
stock-only** functions were rebuilt from disassembly, using donor source where
it existed (`binary-analysis/imgsensor-framework-before-after.tsv` lists all 62):

* custom-LDO power path: `set_custom_ldo` / `unset_custom_ldo`, `do_hw_power_on/off`,
  `adaptor_hw_init` (WL2864C channels via `custom_ldo_en`/`custom_ldo_vout`);
* camera-open charger high-voltage toggle: `imgsensor_high_voltage_supply`
  (`mtk-master-charger` power-supply, `yft_cam_open_flag`) in `imgsensor_open/close`;
* YFT devinfo/CTS: `search_sensor` registers every DT sensor name with
  `yft_camera_device_add`; `notify_fsync_mgr` → `yft_set_camera_device_used`;
  `common_get_imgsensor_id` and every vendor ID probe gated by `is_yft_cts_board()`;
* reg8 I2C helpers `adaptor_i2c_reg8_rd_u8/wr_u8`;
* night-LED for sensor idx 4 (`yft_ctrl_nightled_by_idx`, `flashlight_drvctrl`) driven
  from `V4L2_CID_MTK_SENSOR_POWER` / `_SENSOR_INIT`;
* MTK-base (not Nothing) variants of logging/margin code (Volla MT6878 donor) and
  `__LINE__`-dependent BUG/log sites matched by line placement.

### Sensor sub-drivers — 95 functions, 95 exact
All data (static_ctx, mode tables, frame descriptors, power sequences, register
tables, ana-gain tables, feature lists, ops) is **regenerated byte-exact** from the
stock module into `<sensor>_stock_data.h` by `gen_sensor_data.py` (types from DWARF of
a donor object, values/relocations from stock). Code:

| sensor | basis | vendor logic written from disassembly |
|---|---|---|
| imx989 | NothingOSS imx989 (same driver revision) | ID probe + CTS gate, `open` without LBMF/cali, `imx989_awb_gain` |
| imx989cts | imx989 | ID = chip-ID − 1, accepted only when `is_yft_cts_board()==1`; 12-bit test-pattern channels, regs 0x0607/0x0609 |
| ov64b | NothingOSS ov64b (older revision) | 3-byte ID probe + CTS gate, `open`, init_ctx log; QSC/seamless removed |
| s5kjn1 / s5kjn1cts / s5kjn1main2 | none (generated, `mk_s5kjn1.py`) | dual byte-order ID probe (cts: −1 + CTS-only; main2: low+1 → 0x38E2), sensor_init inlined in `open` (writes from stock), 4-cell EEPROM loader (A0, 0x0D4F…), `custom_streaming_control`, main2 QSC |
| s5kgm2sp / s5kgn1sp | none (generated, `mk_s5kgx.py`) | ID probes (gn1sp: DRV_LOG_MUST enter/out traces), 30/56 KB sensor_init register lists, gn1sp AWB gain (0x0D82–0x0D86) |
| ov32b40 | MTK template (`s5k3p9sp` set_ctrl_locker) | OV group-hold 0x3208, test pattern 0x50C1/0x53C1; uses common open/get_id |

## STOCK-PARITY vs CORRECTED

Stock contains geometry defects in mode tables / frame descriptors. The parity build
reproduces them; the corrected representation lives in separate generated headers
`<sensor>_corrected_data.h`, selected only by `-DGQ5012BF1_CAM_CORRECTED`
(`build.sh … corrected`). The sensor `.c` files contain only the `#ifdef` include
switch, so code is identical in both builds (verified: corrected build has the same
619 functions; only 7 `mode_struct` objects and the replaced frame-descriptor arrays
differ).

Authority for "correct" = the output size the mode's own register table programs
(Sony 0x034C–0x034F, Samsung 0x034C/0x034E, OV 0x3808–0x380B):

| sensor | modes | stock defect | correction |
|---|---|---|---|
| imx989 | 3 hs, 4 slim, 5 cus1, 13 cus9 | RAW VC 4096×2304 / 1920×1080 / 1280×720 / 3296×2460 vs programmed 1920×1080 / 1280×720 / 3840×2160 / 4096×3072 | VC resized (cus9 PDAF VC 3296×615 left, flagged) |
| imx989cts | 3, 4, 5 | same as imx989 | VC resized |
| ov64b | 3 hs, 4 slim | VC 4624×2604 vs 1920×1080 | VC resized |
| s5kgm2sp | 0 prev, 1 cap, 2 vid, 4 slim | VC 4000×**300** (typo), 4640×3488, 2320×1308, 640×480 vs 4000×3000 / 4000×3000 / 4000×3000 / 1920×1080 | VC resized |
| s5kjn1, s5kjn1cts, s5kjn1main2 | 3 hs, 4 slim | TG window 4080×3072 vs programmed 1920×1080 / 640×480 (VC already right) | winsize rebuilt from crop 0x0344–0x034A + 2×2 binning 0x0900 |
| ov32b40 | all | VC sizes ≠ TG 3264×2448 | **UNDETERMINED**: per-mode tables are 10-pair PLL stubs that never program output size (slim even holds a Samsung table) — left as stock |
| s5kgn1sp | – | consistent | – |

## Residual (the only non-identical function)

`yft_ctrl_nightled_by_idx` (172 B both): stock compares `nightled_is_open` with the
full `int state` (`cmp state,#0; ccmp open,state; cset`) and stores that predicate;
this clang build proves `state ∈ {0,1}` from its only two call sites (constants 1 and
0, identical in stock) and emits `cbz`/`cmp open,#1`. Behaviour is identical.
The single-store source form reproduces stock size, so every later function stays
byte-aligned. Variants tried (bool/u8/u32/long `state`, u8 flag, noinline, __used,
per-branch stores, explicit true/false): none reproduces the stock sequence without
changing the caller; passing `ctrl->val` reproduces the comparison but changes
`imgsensor_set_ctrl`, so it was rejected. The build-id differs as a consequence (and
also because lld hashes the unstripped output, whose DWARF contains build paths).
